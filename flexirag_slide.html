Research / Design Thinking
Hybrid Dense + Sparse Retrieval
Pure vector search misses exact-match keyword queries. BM25 fills that gap. Neither alone is sufficient.
Reciprocal Rank Fusion
Score-free list merging. Avoids normalization issues between incompatible score scales across backends.
LLM Reranking
Post-retrieval reordering for contextual fit. Local model keeps this stage cost-free and latency-bounded.
Semantic Caching
Cosine similarity on query embeddings. Catches paraphrases that string-match caching structurally cannot handle.
Modular Stage Design
Each retrieval component independently replaceable. Enables controlled benchmarking across strategies.
Key Engineering Decisions
Fully Local Deployment
Ollama + Sentence-Transformers. Zero API cost, complete data privacy, no external rate limits, no vendor lock-in.
Semantic Cache over String Cache
String matching structurally cannot catch paraphrases. Embedding cosine similarity (threshold 0.85) handles semantically identical queries — 360× speedup on cache hits.
Hybrid Retrieval over Pure Vector
BM25 handles exact-match keyword cases semantic search misses. RRF merge is score-free — avoids normalization complexity across backends.
Auto-Discovery Domain Indexing
Folder structure defines domains — zero config changes when adding document collections. UUID IDs prevent collision on incremental upload.
Auth + Rate Limiting from the Start
Not retrofitted. JWT and rate limiting built in early so the system behaves as a real backend throughout development, not a demo.
CI/CD and Testing from Day One
87 unit tests, 90%+ coverage. GitHub Actions on every commit. Auth, semantic cache, and vector store fully tested in isolation.
